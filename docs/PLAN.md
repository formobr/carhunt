# Car Hunter — критика PRD и технический план (MVP)

Источник требований: [PRD.md](PRD.md). Дата плана: 2026-11-10.

## 1. Критика PRD

| # | Проблема в PRD | Почему важно | Решение в плане |
|---|---|---|---|
| 1 | «Каждое объявление целиком через ИИ» + «минимальные расходы» тянут в разные стороны. | ~100–200 новых объявлений в день, у каждого 5–20 фото. Через подписку это не деньги, а лимиты; Opus на всё быстро их съест. | Двухступенчатая оценка (§4): Haiku 5.5 смотрит **каждое** объявление целиком (текст + фото), Opus 5.5 перепроверяет только кандидатов. Жёстких фильтров до ИИ нет, как требует PRD. |
| 2 | У Facebook Marketplace нет публичного API на чтение. | Это главный технический риск продукта. | Проверено 2026-11-10: с домашнего IP поиск и страница объявления отдаются **без логина** (описание, пробег, коробка, title, все фото, `creation_time`). Аккаунт не нужен, значит, нечему банить. Резерв — Apify (§3). |
| 3 | ToS Meta §3.2.3 запрещает автоматический сбор, в том числе без логина. | Решение по иску Meta v. Bright Data (2024) касалось старых ToS. | Личное использование, 1 запрос на поиск и N на детали раз в 15 минут, без перепродажи данных. Реальный риск — блок IP, а не суд. Детектор блокировки шлёт алерт в Telegram. |
| 4 | Источника «справедливой цены» нет: KBB/Edmunds API закрыты, MarketCheck платный. | ИИ, выдумывающий рыночную цену, хуже честного «не знаю». | Источники: (а) наша статистика по журналу (похожие марка/модель/год/пробег); (б) Opus с `web_search` ищет сравнимые цены только для кандидатов; (в) явное поле «недостаточно данных». |
| 5 | «Не анализировать повторно без причины» — а перепосты? | Продавцы удаляют и перевыставляют то же авто с новым ID. | Дедуп по ID объявления и по отпечатку (марка+модель+год+пробег±1000+город). Перепост — это не новое объявление, но новая цена фиксируется. |
| 6 | Снижение цены — как узнать? | Детальную страницу каждого известного объявления раз в 15 минут не перечитать. | Цена видна в карточках поиска. Каждый опрос сравниваем цены всех карточек с журналом. Снижение ≥ порога → переоценка. |
| 7 | Задержка «публикация → обнаружение». | PRD прямо требует её замерять. | В детальной странице есть `creation_time`. Храним `published_at`, `detected_at`, считаем p50/p90 в `carhunt stats`. |
| 8 | Нет требования к наблюдаемости. | Если FB поменяет вёрстку, бот молча замолчит — это худший отказ. | Каждый запуск пишется в таблицу `runs`. 0 карточек или ошибка парсинга 2 раза подряд → алерт в Telegram. Ежедневная сводка: сколько найдено, оценено, отправлено, сколько потрачено на ИИ. |
| 9 | Мошенничество не упомянуто. | Отдельный класс красных флагов: цена сильно ниже рынка, «машина у военного», доставка, только email. | Добавлено в промпт как красный флаг. |
| 10 | «Бюджет, регион, предпочтения можно менять». | Без админки. | `config.yaml` (цена, город, радиус, модели, пороги) + `prompts/criteria.md` (что такое хорошая машина). Правится текстом, применяется со следующего запуска. |
| 11 | Ложные данные объявлений: пробег 1 или 999999, год в заголовке ≠ год в полях. | ИИ должен видеть противоречия. | В промпт идёт и сырой заголовок, и структурные поля. ИИ обязан отметить противоречие и не верить ему. |
| 12 | Опрос раз в 15 минут — потолок скорости. | Хорошая машина за $4k уходит за час. | Интервал задаётся в конфиге. Старт с 15 мин; когда будет замер задержки, можно опустить до 5–10, если FB не блокирует. |

## 2. Архитектура

```
systemd --user timer (каждые 15 мин) → carhunt poll
  ├─ sources/fb.py        поиск без логина → карточки (id, цена, заголовок, пробег)
  │                       детальная страница новых → описание, поля, фото, creation_time
  ├─ sources/craigslist.py  sapi JSON (последний срез)
  ├─ store.py (SQLite)    listings, price_history, analyses, notifications, runs
  ├─ analyze.py           ступень 1: Haiku 5.5 (текст + до 8 фото) → вердикт
  │                       ступень 2: Opus 5.5 + web_search для «Стоит смотреть»/«Сомнительно»
  ├─ notify.py            Telegram: фото + карточка HTML + кнопка «Открыть объявление»
  └─ health.py            детектор блокировки/поломки парсера → алерт; дневная сводка
```

Стек: Python 3.12, `httpx`, `pydantic`, `pyyaml`, SQLite (stdlib), `pytest`.
ИИ — через подписку владельца: `claude -p` (Claude Code CLI, OAuth уже залогинен на машине), без API-ключа.
Вызов: `claude -p --model <haiku|opus> --setting-sources project --strict-mcp-config --no-session-persistence
--allowedTools Read[,WebSearch] --output-format json --json-schema <схема>`, cwd — временная папка со скачанными фото,
stdin закрыт, жёсткий таймаут, процесс умирает после ответа. Проверено 2026-11-10: Haiku прочитал фото и вернул
`structured_output` за ~10 с. `--bare` не подходит: он не читает OAuth.
Без Playwright: сейчас хватает простого HTTP, а Chromium дорог и легко детектится.

## 3. Источник Facebook

- Поиск: `https://www.facebook.com/marketplace/pittsburgh/vehicles?maxPrice=6000&sortBy=creation_time_descend&exact=false`,
  полный набор заголовков Chrome (Accept, Accept-Language, Sec-Fetch-*), иначе HTTP 400.
- Парсинг: JSON внутри `<script type="application/json">` (`marketplace_search` → `edges` → `listing`).
  Без регулярок по вёрстке.
- Деталь: `https://www.facebook.com/marketplace/item/<id>/` → `redacted_description`,
  `vehicle_odometer_data`, `vehicle_transmission_type`, `vehicle_title_status`,
  `vehicle_make/model/trim_display_name`, `listing_photos[].image.uri`, `creation_time`, `location_text`.
- Вежливость: детали новых объявлений по одной, пауза 2–5 с со случайным разбросом, максимум 30 деталей за запуск.
- Признаки блокировки: HTTP 4xx/5xx, редирект на `/login`, 0 карточек при `has_next_page`. 2 запуска подряд → алерт в Telegram. Apify (~$1.5–6 за 1000) подключаем, только если блокировка реальна и держится.

## 4. Оценка ИИ

Ступень 1 — **Haiku 5.5**, каждое новое объявление:
вход — заголовок, поля, описание, цена, до 8 фото (уменьшенных); выход — строгая схема (structured outputs):

```
verdict: worth_seeing | doubtful | skip
reliability: 0-100, value: 0-100
summary, reasons_for[], risks[], expected_costs
market_price: {low, high, basis} | null, negotiation_target | null
questions_for_seller[], needs_clarification_urgent: bool
facts_unknown[]   — что ИИ не знает (а не выдумывает)
```

Ступень 2 — **Opus 5.5**, только `worth_seeing`, `doubtful` и `needs_clarification_urgent`: та же схема,
плюс `web_search` (до 3 поисков) для сравнимых цен и известных болячек конкретного мотора и коробки.
Плюс статистика похожих машин из нашего журнала. Итоговый вердикт — за ступенью 2.

Уведомление: `verdict == worth_seeing` или `needs_clarification_urgent`. Модели, effort и пороги задаются в `config.yaml`.
Денег за токены нет (подписка), но есть лимиты подписки. Поэтому двухступенчатость остаётся, а на каждый вызов пишутся
длительность и `modelUsage` из JSON-ответа. Лимит вызовов в час задаётся в конфиге. Упёрлись в лимит подписки → объявление
остаётся в очереди `pending_analysis` и оценивается в следующем запуске, сам опрос не останавливается.

## 5. Журнал (SQLite `data/carhunt.db`)

- `listings` — id, source, url, title, year, make, model, trim, mileage, transmission, title_status, location, description,
  photos(json), published_at, detected_at, fingerprint, status
- `price_history` — listing_id, price, seen_at
- `analyses` — listing_id, stage, model, verdict, scores, json, cost_usd, created_at, reason (new / price_drop)
- `notifications` — listing_id, sent_at, telegram_message_id
- `runs` — started_at, source, cards, new, errors, duration
- CLI: `carhunt log [--verdict ...] [--days N]`, `carhunt stats` (задержка p50/p90, расход, воронка), `carhunt show <id>`.

Telegram: TELEGRAM_BOT_TOKEN / TELEGRAM_CHAT_ID из env или `.env` (без запасного бота). От владельца
ничего не требуется. Инструмент скорее одноразовый, поэтому без резервов и админок.

## 7. Готовность MVP (из PRD) → как проверяем

- Регулярное обнаружение: `carhunt stats` показывает запуски каждые 15 мин без пропусков.
- Каждое оценено: число `listings` без `analyses` равно 0.
- Плохие молчат, хорошие приходят: доля уведомлений и ручная проверка 20 карточек.
- Нет дублей: уникальность по id и отпечатку, тест на перепост.
- Снижение цены → переоценка: тест плюс живой случай.
- Задержка замеряется: p50/p90 в `stats`.
